## Findings reproduced and fixed

| Finding | Resolution and regression evidence |
|---|---|
| MCP flash bypassed GUI close/busy checks and headless shutdown | Shared administrative guard blocks GUI reconnect/close; headless shutdown waits for write completion. Actor regression checks mutation refusal during flash and that revoke does not abandon it. |
| Hardware ownership followed wrappers while native workers could outlive them | Arc claims follow BLE writers/disconnect workers, Linux/Windows capture threads and macOS capture Session/start/stop lifetime. Shared hardware claims exclude firmware writes. Simulated detached-worker and shared/exclusive lock tests cover the ownership primitive. Physical teardown timing remains unverified. |
| Pair/unpair bypassed claims; capture aliases could use different claims | All supported pairing operations take adapter/hardware claims; native capture paths are canonicalized where possible. Case folding is limited to adapter identities and Windows. |
| Raw evidence was checked before receipt writes/scheduling | Worker rechecks connection, epoch, freshness and scene immediately before effects, after durable intent. Wrong-connection and stale-frame regressions; physical observation/action races remain bounded rather than eliminated. |
| Emergency release was not counted while awaiting acknowledgement | Release uses the existing ordered/counting pump. Simulated delayed-ACK test proves new input stays blocked. |
| Progress cursor advanced only in memory | Every externally published progress revision is durable. Restart regression proves monotonicity; routine frame polls are excluded. |
| Progress cache changed before a failed durable write | Cache publishes after successful persistence; failures cancel and refuse misleading unchanged replies, then retry. Actor regression removes/restores the receipt directory to reproduce failure and recovery. |
| OCR held capture/actor state for seconds | Snapshot under the capture mutex, then OCR/encoding on a bounded worker; publish only with matching epoch/access generation. Audio lookup uses a worker too. |
| Delayed answers could approve a new confirmation | Unique question IDs bind full-mode answers. Script and workflow status expose the ID. Stale-question regression proves the new question remains unanswered. |
| Prelaunch errors stranded starting receipts | Post-receipt preflight errors finalize as refused. Resume failure regression covers this path. |
| Multiple secret-free headless approvals depended on final GUI selection | Secret-free approved definitions can start independently; credentials remain bound to the current local GUI selection. |
| Same request ID could mean changed parameters | In-memory parameter fingerprints reject mismatches; after owner restart, old IDs are refused with their existing run ID. Typed-content fingerprints are not persisted. Replay regression verifies all three cases. |
| Five-second wording overstated an absolute completion bound | Described as an action budget checked between protocol calls; in-flight acknowledgements and release cleanup may take longer. |

Final static verdict: **no confirmed implementation blocker remains from this review**, subject to native software and
client checks by the implementing agent. Reviewer inspected the new assertions but did not run tests or hardware.

Post-verdict check: refusing approval/start while the selected setup form has unsaved choices was also reviewed and cleared. The regression contrasts saved license acceptance with an unsaved refusal.

## Limits retained

This is not hardware sign-off or proof of end-to-end OOBE, tenant authenticity, physical laptop identity or successful
enrollment. Client JSON-RPC smoke is separate from a real Claude/Cowork installation pass. Full control can bypass
workflow restrictions. The local command actor still adapts the existing egui App execution paths; this is not a claim
that every runtime field has been extracted into a GUI-independent domain crate.
